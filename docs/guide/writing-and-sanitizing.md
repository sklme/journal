# 写作与脱敏

## 写作流程

1. 从开发、排障或技术讨论中提取值得长期复用的结论。
2. 复制知识模板，按主题整理问题、原理、方案和适用边界。
3. 删除过程流水、业务背景和非必要细节。
4. 用自己重新编写的最小示例替代公司代码。
5. 把名称、地址和用户标识替换为公开占位符。
6. 移入仓库后运行 `pnpm check`。
7. 提交前再次人工阅读完整 diff。

## 建议占位符

| 原内容类型 | 公开替代值 |
| --- | --- |
| 域名 | `example.com` |
| IPv4 地址 | `192.0.2.1` |
| 用户标识 | `<USER_ID>` |
| 项目名称 | `Project A` |
| 服务名称 | `Service A` |
| Token | `<TOKEN>` |

## 禁止发布

- 密码、Token、Cookie、私钥、证书和真实配置值。
- 内网域名、仓库地址、服务部署信息和网络拓扑。
- 用户数据、员工信息、账号标识和未公开业务数据。
- 原始日志、抓包内容、数据库导出和协议文件。
- 未经授权的公司源码、设计文档和产品路线。
- 未完成脱敏的截图、文件名、分支名和提交信息。

::: warning 自动检查的边界
自动扫描擅长发现格式稳定的凭据、地址和身份信息，但无法理解一段架构描述是否属于商业秘密。扫描通过不等于允许公开。
:::

## 泄露处理

如果已经提交真实凭据，首先吊销或轮换凭据，然后停止 Pages 发布并清理 Git 历史。仅删除页面或创建一个“修复提交”不足以消除已经公开的内容。
