# 将 MacBook 配置为远程开发机：系列总览

一台闲置的 Apple Silicon MacBook 可以承担构建、测试、命令行任务和容器开发。客户端负责输入与显示，MacBook 负责运行项目。本系列从持续在线到实际开发逐步配置，并将具体软件故障放在独立排障文章中。

原来的配置文章入口保留为系列总览。首次搭建时按下面的顺序阅读；已有可用环境时先检查状态，再补充缺少的部分。

## 配置前明确三个执行位置

| 执行位置 | 负责的事情 |
| --- | --- |
| 服务端 MacBook | 供电与睡眠设置、远程登录权限、屏幕共享、项目工具与进程 |
| 客户端电脑 | Tailscale、SSH 私钥与连接配置、远程 IDE、网页端口转发 |
| iPhone 或 iPad | Tailscale、SSH 或屏幕共享客户端、触控与按键操作 |

SSH 密钥在客户端生成，公钥可以通过首次密码登录写入远端。服务端无需现场操作即可完成这一步。各连接设备分别使用自己的密钥，便于独立撤销访问。

各篇使用通用参数：`<USER_ID>` 是 Mac 账户短名称，`<TAILSCALE_IP>` 是目标设备的组网地址，`<VERSION>` 是项目要求的运行时版本。替换参数后再执行命令；原理说明与示例不代表已经修改读者的机器。

## 教学与复现约定

每篇先说明要解决的问题与前提，再给出执行位置、操作步骤、预期结果和验收方法。人工操作或交给 AI 执行时，都按以下顺序处理：

1. **确认环境**：记录服务端与客户端的系统版本、当前网络和目标账户；先读取已有设置与工具状态。
2. **填入参数**：将示例账户、地址、目录和版本替换为实际值。参数未知时先查明，不能直接执行占位符。
3. **逐步操作**：已经符合预期的步骤可以跳过。GUI 按入口与选项名称定位，命令按标注的执行位置运行；安装和项目配置按实际需要选择。
4. **立即验证**：每一步读取保存后的状态，并执行对应验收。失败时先记录现象，再进入排障；不要继续把后续步骤记为成功。
5. **保留结果**：记录测试条件、实际输出与结论。服务端自测、客户端登录、外网连接和重启恢复分别记录，避免扩大验证范围。

可以用下面的记录格式交接给下一位操作者或 AI：

| 步骤 | 执行位置与测试条件 | 预期结果 | 实际结果或证据 | 状态 |
| --- | --- | --- | --- | --- |
| 示例：客户端 SSH 登录 | 客户端电脑；外部网络；目标账户已核对 | 新连接成功，`whoami` 为目标账户 | 填写输出或错误，不粘贴密码与私钥 | 待验证 / 通过 / 失败 |

排障文章采用“现象 → 复现条件 → 分层检查 → 原因或证据 → 处理 → 复测”的结构。历史观察标明日期；没有证据支持的原因和未完成的测试明确保留为待确认。

## 按用途选择连接入口

| 目的 | 入口 |
| --- | --- |
| 执行命令、构建和测试 | SSH；需要断线后接续时使用 tmux |
| 在日常电脑编辑远端代码 | 远程 IDE；开发进程在 MacBook 上运行 |
| 操作系统设置、桌面 App 和图形界面 | 屏幕共享 |
| 用手机临时查看进度或处理任务 | 手机 SSH 客户端或屏幕共享客户端 |

Tailscale 提供网络连通性，SSH 和屏幕共享各自提供认证与操作入口。锁屏、系统睡眠、网络在线和应用会话加载是不同状态，遇到问题时分别判断。

## 当前验证范围

截至 2026-10-11，实机已核对接电防休眠、30 分钟熄屏、立即要求密码、Tailscale 在线、SSH 与屏幕共享的服务响应、指定账户权限，以及运行中的 tmux 会话。桌面远程访问的配置完成也得到操作者反馈。

服务端向自己的组网地址连接，只能验证服务响应，不能代替另一设备的登录和外网验收。熄屏后新建连接、手机切换外网、项目健康检查与实际重启恢复，仍应按第六篇逐项记录。2026-10-10 的 Codex 手机旧会话故障单独保留在排障篇，不能由主机配置正常推断其已经修复。

容器、持续服务与备份按实际项目需要安排。先完成当前用途所需的连接与开发路径，再逐步增加维护能力。
