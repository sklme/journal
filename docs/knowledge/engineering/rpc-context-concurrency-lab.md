## 要证明什么

**调用必须确实重叠执行，而且重叠期间每条执行链都读取自己的路由和请求标识。** 只看耗时变短，无法排除“更快地用了错误路由”。

本篇把前四篇的机制整合为一个可下载实验。代码独立使用 Node.js 标准库编写，不加载业务框架，不保留内部模块适配路径或原项目的运行结论。

实验中的 HTTP 请求只是模拟的异步执行范围；RPC 只是经过一次事件循环等待后读取状态的函数。它不启动服务、不访问网络，也不验证真实入口鉴权或传输协议。

## 下载与执行

下载[完整实验脚本](/examples/rpc-context-concurrency-lab.mjs)，保存为 `rpc-context-concurrency-lab.mjs`，使用 Node.js 22：

```bash
node --test rpc-context-concurrency-lab.mjs
```

无需安装依赖。测试使用内置的 `node:test`、严格断言、ALS 和 AsyncResource。失败会以非零退出码结束，适合将模型作为框架适配时的回归基线。

## 八个测试覆盖哪些性质

| 测试 | 必须成立的断言 |
| --- | --- |
| 共享状态反例 | 明确屏障后，A 读到 B 覆盖的值 |
| 请求内串行队列 | 最大在途数为 1，父路由恢复 |
| 子上下文并发 | 最大在途数为 3，同路由和不同路由分支均隔离 |
| 两个请求交错 | 每个请求的标识、路由和选项保持正确 |
| 嵌套分支 | 内层结束后外层对象、路由和选项不变 |
| 同步与异步失败 | 失败原因保留，成功分支与父状态不受污染 |
| 队列失败恢复 | 前一操作拒绝后，后续操作仍然执行 |
| 请求范围之外 | 状态为 `undefined`，无父状态的子操作拒绝 |

## 顺着实验理解执行边界

### 一个访问入口，多个执行范围

整个脚本只创建一个 `scope`。它的 `state` getter 每次从当前 ALS 环境获取 store。`request()` 为不同请求创建新对象，并通过 `run()` 启动工作。

这允许客户端共用访问入口，但不意味着客户端可以把当前路由缓存为自己的可变成员。实验在等待前后都读取 scope，以覆盖异步恢复后的状态。

### 用屏障固定竞争顺序

共享状态反例让任务 A 写入后等待，外层覆盖路由再释放 A。它必须稳定复现覆盖结果，而非运行很多次才偶尔失败。

这个反例说明的是对象共享，不是上下文丢失，也不需要多线程。确认问题类型后，才能选择正确修复方法。

### 队列只对自己的父状态负责

`lockedRouter()` 在请求内创建，记录状态对象作为所有者。任务获得执行机会后才设置路由，等待操作结束再恢复；队列不会吞掉调用方收到的拒绝，只把内部排队链恢复为可继续状态。

它不支持重入、超时或取消。若持锁任务嵌套等待同一队列会死锁；实际系统需要按需求选择成熟的锁实现，不能直接把教学模型当作通用调度器。

### 隔离必须早于任务启动

`branch()` 先复制状态和顶层选项，再在新 AsyncResource 范围中注册状态，最后调用业务函数。父状态没有被临时修改，所以结束时无需恢复父路由。

这份模拟约定注册方法使用 `enterWith()`。AsyncResource 提供该注册动作的执行边界；拥有 ALS 的应用也可以直接使用 `run()`。[Node.js AsyncResource 参考](https://nodejs.org/download/release/v22.17.1/docs/api/async_context.html#class-asyncresource)

`emitDestroy()` 的调用与操作返回的 Promise 对齐。业务函数必须返回覆盖全部工作的 Promise；未等待的后台任务不会因资源销毁通知自动停止。

### 用在途量而不是毫秒数断言并发

`measure()` 在进入模拟 RPC 时增加计数，完成或失败时在 `finally` 中减少。`setImmediate` 提供一次事件循环交错机会；测试断言锁模式峰值为 1，子状态模式峰值为 3，不要求在某个毫秒阈值内完成。

两次相同的路由使用不同选机选项，确保测试不只覆盖“路由值不同”的情况。两个请求各自计数，也避免把全局并发误报为单请求并发。

### 对象身份与字段都要检查

测试不仅比较值，还检查执行范围返回后 `scope.state` 仍是原父对象。嵌套测试让内外层分别修改顶层选项，验证内层改动不影响外层和父层。

失败测试等待所有分支结束，检查拒绝原因和成功值。只验证 Promise 被拒绝，不能证明其他分支或父状态没有被污染。

## 本次验证结果

2026-09-16，在 Node.js `v22.23.2` 执行随文脚本，8 个测试全部通过：锁模式最大在途数为 1，子上下文模式为 3，两个交错请求各自也为 3；嵌套、同步异常、异步拒绝、队列恢复及无父上下文断言全部成立。

这是本次通用脚本的运行结果，不代表任何生产框架、服务或接口已经通过回归。前三篇和第四篇的六段独立 JavaScript 示例也已分别执行通过。

## 换成真实框架后还需要做什么

先核对框架对状态注册、读取、对象复制与生命周期的契约，再改写适配层。不要为了通过测试绕过真实客户端的状态读取。

应在真实编码和发送边界增加断言，确认下游实际收到预期参数；分别验证普通发送与代理发送，以及共享初始化、会话刷新、超时、取消和重试。换成真实 scope 类但仍只等待本地事件循环，并不等于测试了真实传输。

本实验仅复制顶层选项。嵌套对象、连接和 Request 的共享规则仍须审查；固定三个任务也没有提供生产限并发、授权或资源预算。性能收益应按[第四篇的同条件对照与验收方法](./rpc-concurrency-isolation-boundaries.md)另行验证。
