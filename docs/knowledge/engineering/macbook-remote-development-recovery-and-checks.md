# MacBook 远程开发机：验收、重启恢复与维护

本篇是系列第六篇。目标是把“设置看起来正确”转化成可以复测的结果，并明确机器重启之后的恢复步骤。

## 前提与记录方法

- 已完成当前用途所需的网络、SSH、屏幕共享和开发环境。
- 测试前记录系统与客户端版本、供电状态、网络、目标账户、预期结果和实际结果。
- 熄屏与重启分开测试。实际重启会结束正在运行的任务，应先保存工作，并在有人能够现场恢复时进行。
- 未测试的项目记为“待验证”，不要从某一项成功推断整条链路成功。

## 原理：持续在线与重启恢复

接电开盖、防止闲置睡眠，是持续运行的基础。日常维护还需要完成以下安排：

- 保留磁盘加密与系统更新，记录维护后的恢复步骤。
- 检查 Tailscale 设备密钥到期与访问策略，确保外出期间不会因凭据状态失去连接。
- 将代码和运行时版本纳入版本管理，数据库与其他持久化数据单独备份。
- 持续运行的服务使用合适的服务管理或容器重启策略；交互任务使用 tmux。
- 在有人能接触机器时，完成一次实际重启验收，并记录需要人工介入的步骤。

FileVault 的恢复能力取决于硬件、系统版本和网络条件。Apple 说明，Apple Silicon Mac 在 macOS 26 及以后可以在开启 Remote Login 且网络可用时，通过 SSH 在重启后解锁 FileVault。**这不证明安装的 Tailscale GUI 客户端在该阶段已经可达**，也不证明用户登录服务已经运行。参见 [Apple 的 FileVault 管理说明](https://support.apple.com/en-gb/guide/security/sec8447f5049/web)。未完成远程解锁验证时，应准备现场首次解锁的恢复方式。

## 验收：先验证熄屏，再验证网络与恢复

| 验收项 | 操作 | 通过标准 |
| --- | --- | --- |
| 配置保存 | 重新打开电池选项，并读取 `pmset -g custom` | 防止自动睡眠开启，接电分组为 `sleep=0`、`displaysleep` 等于设定时长，锁屏界面密码要求为立即 |
| 熄屏后的连接 | 接电开盖，不操作 MacBook，等待超过设定熄屏时长（本系列示例为 30 分钟）；从客户端新建 SSH 连接 | 屏幕关闭后仍能登录并执行命令 |
| 屏幕共享 | 熄屏后从客户端新建连接，并从手机外网再测一次 | 目标账户认证成功，能实际控制桌面 |
| 外部网络 | 客户端切换到另一网络，通过 Tailscale 登录 | 能重新连接，确认不是只在本地 Wi-Fi 可用 |
| 断线后的任务 | 在 tmux 中运行可观察任务，断开 SSH 后重新接入 | 会话和进程仍存在，输出继续变化 |
| 容器可用 | 检查 Colima 和 Docker 状态，运行项目的健康检查 | 容器运行且应用响应符合预期 |
| 重启恢复 | 在可现场接触机器时重启，检查解锁、Tailscale、SSH 和服务 | 能恢复连接与项目服务，或已明确记录人工恢复步骤 |

熄屏验证期间持续碰键盘或触控板会重置闲置计时。只看到一个一直未断开的 SSH 窗口也不够，应该新建连接并执行命令。将“配置字段正确”和“完整远程开发链路可用”分别记录。

## 常见错误与排查顺序

| 现象 | 优先检查 |
| --- | --- |
| 屏幕关闭后无法连接 | 实际是否接电、是否合盖、接电分组的睡眠值、私有网络是否在线 |
| 手机能运行新任务，但旧任务重连失败 | 会话恢复和历史加载；单独核查相关客户端错误，不直接归因于锁屏或整个主机离线 |
| Tailscale 在线，但 SSH 被拒绝 | Remote Login 是否开启、账户是否在允许列表、私有网络访问策略 |
| SSH 可用，但开发命令找不到 | 远程 Shell 初始化、Homebrew 路径、运行时管理器的激活与项目版本 |
| SSH 断开后任务结束 | 任务是否运行在 tmux 或服务管理器内，而不是直接依附于登录会话 |
| Docker 客户端无法连接 | Colima 是否运行、当前 Docker context、服务是否需要用户登录后启动 |
| 重启后机器失联 | 当前解锁阶段、基础网络、Tailscale 启动方式和服务恢复流程 |

排查时先确认状态，再修改设置。保留可用连接或现场恢复能力后，再调整登录认证、网络权限和服务启动方式。

## 重启验收：按恢复阶段定位

1. **重启前**：保存工作，记录当前连接地址、项目启动方式和现场恢复途径。
2. **FileVault 解锁阶段**：确认基础网络和 SSH 解锁路径实际可用；不要假设 Tailscale 在这一阶段已经在线。
3. **用户登录阶段**：确认 Tailscale 与需要的登录项启动，客户端能重新看到设备。
4. **服务恢复阶段**：分别验证 SSH、屏幕共享、容器后端和项目健康检查。
5. **记录结论**：写明哪些自动恢复、哪些需要人工解锁或重新启动。tmux 原进程被重启结束后，应按记录重新创建工作会话。

若需要人工介入，记录完成该步骤的人和方式即可判断当前方案的适用范围。具体软件在未登录阶段的可用性由本机测试确认。

## 磁盘空间：空闲与可用采用不同口径

`df -h /System/Volumes/Data` 显示当前文件系统空闲情况。macOS“磁盘工具”的“可用”还可能包含系统按需回收的可清除空间。因此不能只读 `df` 的空闲列或使用率，就认定这台 Mac 没有足够容量。[Apple 容量说明](https://support.apple.com/en-ie/guide/disk-utility/dskutl1005/mac)

例如一个说明性的容量组合：

| 项目 | 示例值 |
| --- | --- |
| 当前空闲空间 | 20 GB |
| 可清除空间 | 200 GB |
| 包含可清除内容的可用容量 | 220 GB |

在“磁盘工具”选择实际的数据宗卷，核对空闲、可清除和可用；系统设置的分类统计也可能仍在计算。需要大规模下载、构建或扩展容器磁盘时，再结合实际写入需求判断。

## 后续维护按用途安排

- 外出前检查 Tailscale 设备密钥到期与访问权限，确认有恢复登录的方式。[Tailscale 密钥到期说明](https://tailscale.com/docs/features/access-control/key-expiry)
- 更新系统或网络客户端后，复测一次新连接与当前项目。
- 新增客户端时，从该客户端生成独立 SSH 密钥并验证；服务端仅保存公钥。
- 代码与运行时声明纳入版本管理，数据库和其他持久化数据按需要安排备份。备份详细配置可以在明确目标和介质后另做专题。

## 验证记录与边界

2026-10-11 已读取核对：接电防闲置睡眠、显示器 30 分钟熄屏、此前 GUI 保存的立即要求密码、Tailscale 在线、SSH 与屏幕共享仅允许目标账户、两项服务在本机回环及本机组网地址有协议响应，tmux 会话存在。操作者另反馈远程桌面配置完成。

上述协议响应来自服务端对自身地址的检查，不是另一设备的登录验收；运行中的 tmux 列表也不等于任务断线接续测试。手机移动网络、实际项目健康检查与重启恢复未在这组检查中完成。有关手机 Codex 的新旧任务对照应在 [独立排障篇](../ai-engineering/codex-mobile-session-reconnect-troubleshooting.md)中记录。
