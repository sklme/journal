# tmux 实用指南：常用命令、会话管理与远程开发

tmux 适合把终端工作留在一台机器上持续运行：电脑关闭终端、手机断开 SSH 后，再连接同一台机器，就能回到原来的工作界面。本文面向已经安装 tmux、练习过创建和重新进入会话的读者，重点解决日常操作记不住的问题。

命令示例以 macOS 为主，基础操作同样适用于 Linux。会话名 `dev`、`work` 和 SSH 别名 `devmac` 都是通用示例。基础命令可在 Zsh 或 Fish 中使用；练习中的循环明确交给 `sh` 执行。

本文同时是 [MacBook 远程开发机系列](./macbook-remote-development-setup.md)的第四篇。先完成 [网络与 SSH](./macbook-remote-development-network-and-ssh.md)；需要图形界面时阅读 [屏幕共享篇](./macbook-remote-development-screen-sharing.md)。

## 日常速查：先记住这些

本文把默认前缀 **Ctrl + B** 写成 **前缀**。每次先同时按 Ctrl 和 B，松开两个键，再按表中的后续键。例如“前缀 → D”就是 **Ctrl + B，松开，再按 D**，输入的是小写 `d`。

| 想做什么 | 操作 | 在哪里使用 |
| --- | --- | --- |
| 进入 `dev`，没有就创建 | `tmux new -A -s dev` | tmux 外的命令行 |
| 查看有哪些会话 | `tmux ls` | 命令行 |
| 回到已有会话 | `tmux attach -t dev` | tmux 外的命令行 |
| 离开 tmux，任务继续运行 | 前缀 → D | tmux 内 |
| 查看并切换会话 | 前缀 → S | tmux 内，输入小写 `s` |
| 查看会话和窗口树 | 前缀 → W | tmux 内，输入小写 `w` |
| 新建窗口 | 前缀 → C | tmux 内，输入小写 `c` |
| 切换到窗口 1 / 2 | 前缀 → 1 / 2 | tmux 内 |
| 把当前区域左右分屏 | 前缀 → `%` | tmux 内 |
| 把当前区域上下分屏 | 前缀 → `"` | tmux 内 |
| 切换分屏区域 | 前缀 → 方向键 | tmux 内 |
| 放大当前分屏，再按恢复 | 前缀 → Z | tmux 内，输入小写 `z` |
| 查看历史输出 | 前缀 → `[` | tmux 内 |
| 查看快捷键帮助 | 前缀 → `?` | tmux 内 |

符号键要输入实际符号，例如常见美式键盘上的 `%` 是 Shift + 5，`"` 是 Shift + 单引号。手机或平板可以使用 SSH 客户端的 Ctrl 键和符号键栏。

记忆可以从三组开始：**进入与离开、查看与切换、新建与分屏**。其他操作用帮助界面查，不必一次背完。

## 核心原理：会话、窗口和分屏

| 层级 | 作用 | 典型安排 |
| --- | --- | --- |
| 会话 Session | 保存一组相关工作 | 一个项目一个会话：`dev`、`work` |
| 窗口 Window | 会话中的一张终端页面 | `code`、`server`、`logs` |
| 分屏 Pane | 同一窗口中可同时看到的终端区域 | 左侧执行命令，右侧观察日志 |

tmux 的“窗口”显示在终端应用内部，和 Terminal 或 Ghostty 的系统窗口、标签页是两层东西。

例如 `dev` 会话可以包含 `1:code`、`2:server` 和 `3:logs` 三个窗口，每个窗口再按需要分成几个 pane。底部状态栏显示当前会话和窗口列表，窗口名后面的 `*` 通常标记当前窗口。

tmux 的后台进程管理这些终端。连接到它的客户端负责显示和输入，因此离开客户端后，会话仍可存在。官方 [Getting Started](https://github.com/tmux/tmux/wiki/Getting-Started) 介绍了这一结构。

## 最小配置：沿用默认按键

macOS 可以通过 Homebrew 安装并查看版本：

```sh
brew install tmux
tmux -V
```

已经安装时直接查看版本即可。把下面内容合并到 `~/.tmux.conf`；已有配置时先阅读并保留自己的设置。

```text
# 使用鼠标选择 pane、拖动边界和滚动历史。
set -g mouse on

# 每个 pane 的历史输出最多保留 20000 行。
set -g history-limit 20000

# 窗口和 pane 的编号从 1 开始。
set -g base-index 1
setw -g pane-base-index 1

# 关闭窗口后，整理剩余窗口的编号。
set -g renumber-windows on
```

tmux 服务启动时读取配置。已经有会话在运行，可以重新加载：

```sh
tmux source-file ~/.tmux.conf
```

在 tmux 内，也可以按“前缀 → `:`”，输入 `source-file ~/.tmux.conf` 并回车。这个命令提示行中省略开头的 `tmux`。

配置加载后，窗口的实际编号以状态栏为准；改变 `base-index` 不会保证已有窗口立即从 1 排列。历史行数设置用于之后新建的 pane，不会补回已经丢弃的输出。配置保留默认 Ctrl + B 前缀，没有设置复制模式的按键风格。

## 会话管理：创建、回来、切换和结束

### 在 tmux 外管理会话

下面各行是独立操作，按需要执行：

| 操作 | 命令 | 说明 |
| --- | --- | --- |
| 创建或进入 | `tmux new -A -s dev` | `dev` 存在就进入，否则新建 |
| 只创建新会话 | `tmux new -s work` | 同名会话已经存在时会报错 |
| 列出会话 | `tmux ls` | 查看名称、窗口数和连接状态 |
| 进入已有会话 | `tmux attach -t dev` | 会话不存在时会报错 |
| 给会话改名 | `tmux rename-session -t dev work` | `work` 不能已经被其他会话占用 |
| 查看连接的终端 | `tmux list-clients` | 查看当前接入 tmux 的客户端 |
| 查看某会话的窗口 | `tmux list-windows -t dev` | 查窗口编号和名称 |
| 查看某窗口的分屏 | `tmux list-panes -t dev:1` | 查窗口 1 中的 pane |

`tmux ls` 中的 `(attached)` 表示有客户端正在连接，未连接的会话也能继续执行任务。列表只属于当前机器、当前系统用户和当前 tmux 服务；在手机本地执行和 SSH 登录远端后执行，查的是不同环境。

如果没有运行中的 tmux 服务，`tmux ls` 可能提示 `no server running` 或找不到服务套接字。此时可以用 `tmux new -A -s dev` 开始工作。

### 已经在 tmux 内时切换会话

按“前缀 → S”打开会话列表，方向键选择，回车进入；按 Q 取消。也可以在当前 pane 的 Shell 中输入：

```sh
tmux switch-client -t work
```

已经在 tmux 内时优先使用切换操作。如果再运行普通的 `tmux new` 或 `tmux attach`，可能触发嵌套提示。确实要新建另一个会话并切换，可以分两步：

```sh
tmux new -d -s work
tmux switch-client -t work
```

`-d` 表示创建后先不接入。若 `work` 已经存在，只执行第二行。

### 离开界面和结束任务分别怎么做

| 目的 | 操作 | 结果 |
| --- | --- | --- |
| 回到 tmux 外面的命令行 | 前缀 → D | 当前客户端分离，会话继续存在 |
| 请求停止当前前台任务 | Ctrl + C | 通常向前台程序发送中断，由程序处理 |
| 结束当前 Shell | 在 Shell 提示符处输入 `exit` | 默认设置下，这个 pane 随 Shell 退出而关闭 |
| 强制关闭当前 pane | 前缀 → X，确认 | 关闭该 pane，里面的任务可能被终止 |
| 强制关闭当前窗口 | 前缀 → `&`，确认 | 关闭窗口及其中所有 pane |
| 销毁指定会话 | 下面的 `kill-session` 命令 | 销毁该会话，普通用法下会结束其中的任务 |

确认任务可以结束、需要保存的内容已经保存后，再销毁会话：

```sh
tmux kill-session -t '=dev'
```

这里的 `=dev` 要求会话名精确匹配，避免把名称前缀匹配到其他会话。这个命令没有交互确认。少见的“把同一个窗口链接到多个会话”用法中，另一个会话仍引用的窗口会保留。

普通用法下，最后一个 pane 退出会使窗口关闭，最后一个窗口关闭会使会话结束。`exit` 只有在 Shell 接收输入时才是退出 Shell 的命令；如果当前是编辑器或交互程序，需要按该程序的退出方式操作。

SSH 登录后按“前缀 → D”，会先回到**远端的 SSH 命令行**。要断开 SSH，再在这个远端 Shell 中输入 `exit`；下一次登录后可重新进入 tmux。

## 窗口与分屏：把工作摆清楚

### 窗口快捷键

以下操作都先按前缀：

| 后续键 | 作用 |
| --- | --- |
| C | 创建窗口，输入小写 `c` |
| `,` | 给当前窗口改名 |
| 1～9 | 按编号进入窗口 |
| N / P | 下一个 / 上一个窗口，输入小写 `n` / `p` |
| L | 回到刚才的窗口，输入小写 `l` |
| W | 展开会话和窗口树，输入小写 `w` |

给窗口起 `code`、`server`、`logs` 这样的名字，通常比记住它原来运行的是哪一个 Shell 更容易。按 W 打开树后，可以用左右方向键展开和折叠，用上下方向键选择，再回车。

### 分屏快捷键

以下操作也都先按前缀：

| 后续键 | 作用 |
| --- | --- |
| `%` | 左右分屏 |
| `"` | 上下分屏 |
| 方向键 | 进入对应方向的 pane |
| O | 按编号轮流切换 pane，输入小写 `o` |
| Q，再按数字 | 暂时显示 pane 编号并选择，输入小写 `q` |
| Z | 放大当前 pane，再按一次恢复，输入小写 `z` |
| 空格 | 在预设分屏布局间循环 |

启用鼠标后，可以点击 pane 切换焦点，拖动分隔线调整大小。想通过命令精确调整当前 pane，可以在其 Shell 中执行其中一行：

```sh
tmux resize-pane -R 5
tmux resize-pane -D 3
```

`-R` 表示向右调整 5 列，`-D` 表示向下调整 3 行；实际可调整的空间受当前布局约束。

## 历史输出、搜索和复制

### 回看已经滚走的内容

按“前缀 → `[`”进入复制模式，用方向键和 Page Up / Page Down 浏览。启用鼠标后，滚轮也可进入历史浏览。此时输入先交给复制模式，任务仍可继续产生输出。

复制模式有 Emacs 和 Vi 两种按键风格。查看当前窗口实际使用的风格：

```sh
tmux show-options -w mode-keys
```

| 复制模式中的操作 | Emacs 风格 | Vi 风格 |
| --- | --- | --- |
| 退出历史浏览 | Esc | Q，输入小写 `q` |
| 向较早的输出搜索 | Ctrl + R，输入关键词 | `?`，输入关键词并回车 |
| 开始选择文字 | Ctrl + Space | Space |
| 移动选择范围 | 方向键 | 方向键或 H / J / K / L 的小写键 |
| 复制选区并退出 | Alt + W，输入小写 `w` | Enter |

表中的键在进入复制模式后直接按，**不用再按前缀**。macOS 和手机上的 Alt / Option 传递方式取决于终端应用；Ctrl + Space 也可能被输入法切换占用。如果需要统一为 Vi 风格，可选择在配置中补充 `setw -g mode-keys vi`，再重新加载。

复制以后，按“前缀 → `]`”粘贴 tmux 最近一次复制的内容。按“前缀 → `=`”可以选择之前的复制缓冲。

### tmux 缓冲和系统剪贴板

tmux 自己保存的复制缓冲和电脑、手机的系统剪贴板是不同位置。终端支持的剪贴板协议、终端配置、SSH 客户端和 tmux 选项共同影响自动同步，不能把某一个快捷键当作跨设备剪贴板保证。

当 tmux 运行在当前 Mac 本机时，可以把最近的 tmux 缓冲送到这台 Mac 的系统剪贴板：

```sh
tmux show-buffer | pbcopy
```

SSH 到远端 Mac 后执行同样的命令，写入的是远端 Mac 的剪贴板，手机并不会因此得到文本。手机复制优先使用 SSH 客户端提供的选择和复制功能。

### 导出某个 pane 保留下来的输出

在需要留存当前屏幕和历史时，先查看窗口及 pane 编号，再执行：

```sh
tmux capture-pane -p -S - -t dev:1.1 > /path/to/project/terminal-output.txt
```

把输出路径替换成存在且可写的目录。`dev:1.1` 表示 `dev` 会话的窗口 1、pane 1；`-p` 把内容输出为文本，`-S -` 从仍保留的最早历史行开始。重定向会覆盖同名文件。

pane 历史有上限，而且屏幕中的回车刷新、进度条等未必能还原成完整日志。需要完整任务记录时，应让程序自身写日志。导出文件可能包含命令和业务输出，公开分享前另行检查。

## 典型用法：四个可以直接练习的场景

### 1. 临时离开，稍后回到原来的位置

在 tmux 外创建练习会话：

```sh
tmux new -s practice
```

进入后运行一个只打印时间的任务：

```sh
sh -c 'while :; do date; sleep 2; done'
```

按“前缀 → D”回到外层命令行。稍后执行：

```sh
tmux ls
tmux attach -t practice
```

看到时间输出继续变化，就完成了离开与重新进入练习。结束练习时先按 Ctrl + C 停止循环，再在 Shell 中输入 `exit`。

### 2. 一个项目一个会话，一个用途一个窗口

在 tmux 外进入项目目录，再创建或进入会话：

```sh
cd /path/to/project
tmux new -A -s dev
```

已有会话重新接入时，会保留各 pane 原来的工作目录，外面的 `cd` 不会把它们全部改到新目录。

进入后依次练习：

1. 前缀 → `,`，把第一个窗口命名为 `code`。
2. 前缀 → C，新建窗口；再用前缀 → `,` 命名为 `server`，运行项目的开发服务。
3. 再建一个窗口 `logs`，运行项目实际需要的日志查看命令。
4. 用前缀 → 1 / 2 / 3 或前缀 → W 来回切换。
5. 临时离开时按前缀 → D；下次用 `tmux new -A -s dev` 回来。

如果希望用命令新建窗口并明确指定它的目录，可以在命令行执行：

```sh
tmux new-window -t dev -n logs -c /path/to/project
```

目录要先存在。已经有 `logs` 窗口时，这条命令仍会创建新窗口；窗口名称可以重复。

### 3. 左边执行命令，右边观察任务

在同一个窗口中按“前缀 → `%`”做左右分屏。一个 pane 执行编辑、构建或查询，另一个运行日志查看或 `top`。

用“前缀 → 方向键”切换输入位置。输出太窄时按“前缀 → Z”放大当前 pane，看完再按一次恢复。手机屏幕较小时，这个操作尤其方便。

普通分屏不会把输入同步给所有 pane；命令输入作用于当前 pane。

### 4. 电脑开始工作，手机或平板继续

先确保手机或平板能通过 SSH 连接目标机器；`devmac` 是预先配置好的示例别名，也可以替换为自己的连接目标。

```sh
ssh devmac
tmux new -A -s dev
```

这两行依次完成登录目标机器和接入目标机器上的会话。它们需要使用和原会话相同的远端系统用户。

普通 `attach` 允许电脑和手机同时接入同一会话；输入会作用于共享的终端程序。希望从手机接手并让其他连接离开时，可以在 tmux 外执行：

```sh
tmux attach -d -t dev
```

`-d` 会分离该会话的其他客户端，不会停止会话中的任务。多设备尺寸不同会影响显示和窗口布局，具体取决于 `window-size` 等设置；手机优先用单个窗口或 pane 放大模式。

tmux 保存的是目标机器上运行中的终端。它不会替手机保持 VPN 或 SSH 连接，也不会把本机会话自动同步到另一台服务器。

## 常见问题与适用边界

| 现象或问题 | 原因与处理 |
| --- | --- |
| Ctrl + B 后没有进入操作 | 松开 Ctrl 和 B，再按后续键；确认客户端能发送 Ctrl |
| `duplicate session` | 只创建的命令遇到同名会话；改用 `tmux new -A -s dev` |
| `can't find session` | 检查会话名、所在机器和系统用户；用 `tmux ls` 确认 |
| 提示会话可能嵌套 | 已经在 tmux 内；用前缀 → S 或 `tmux switch-client` 切换 |
| 看历史时无法输入命令 | 正处于复制模式；按对应风格的退出键回到终端输入 |
| 关闭了 pane 后找不到任务 | 任务依附于被关闭的终端；关闭前先确认它能结束 |
| 重启后没有原会话 | tmux 默认保留运行中的会话，重启会结束进程 |
| 屏幕已经熄灭，任务还会不会跑 | 只熄屏且系统保持唤醒时可以；系统休眠时任务暂停执行 |

需要区分三个持续性层次：

- **终端断线后继续工作**：tmux 能保留其中运行的任务，前提是主机和 tmux 服务仍正常运行。
- **任务退出后自动重启**：需要程序自身、服务管理或容器的重启策略。
- **机器重启后恢复工作**：需要重新启动任务；一些插件可以帮助重建布局或命令清单，不能让已经终止的进程从原执行位置继续。

系统断电、重启、用户登出清理进程、tmux 服务被结束或任务自身崩溃，都可能结束工作。长期无人值守服务应使用适合平台的服务管理方式。Mac 的在线、电源和 SSH 配置见 [将 MacBook 配置为远程开发机](./macbook-remote-development-setup.md)。

## 验证记录与复习方法

本文基础配置和命令在 macOS、tmux 3.8 的隔离测试服务中验证。验证范围包括：配置读取、会话创建与改名、窗口与分屏编号、历史输出捕获、客户端分离后任务继续输出、重新接入，以及指定会话清理。快捷键和复制模式操作核对了该版本自带的手册与默认绑定。

这些检查没有覆盖每款手机 SSH 客户端的按键栏、输入法、触控选择或跨设备剪贴板。实际接入时，需要在使用的客户端中再练习一次前缀、分离、滚动和复制。

忘记按键时，先用“前缀 → `?`”打开帮助；离开帮助可按 Q。命令行也可以查看本机完整手册：

```sh
man tmux
```

复习时按“新建会话 → 新建窗口 → 分屏 → 切换 → 放大 → 分离 → 重新进入 → 停止练习任务”的顺序练一遍。日常先稳定使用这条路径，再逐步增加搜索、复制和布局操作。

## 公开参考

- [tmux 官方 Getting Started](https://github.com/tmux/tmux/wiki/Getting-Started)：概念、默认按键和基础使用。
- [tmux 官方源码中的手册](https://github.com/tmux/tmux/blob/master/tmux.1)：命令、目标选择、配置和复制模式的完整定义；在线主分支可能与本机版本不同。
- [OpenBSD tmux 手册](https://man.openbsd.org/tmux.1)：可浏览的命令参考。

具体行为以本机 `tmux -V` 对应的 `man tmux`、当前配置和实际按键绑定为准。
