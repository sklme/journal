# 搭建个人开发札记

## 背景

开发过程中的很多判断只存在于临时对话、终端历史和记忆里。最终代码通常无法解释为什么采用当前方案，也很难在下一次遇到类似问题时快速复用。

这个站点用于保存两类内容：

- 按时间记录的问题排查和实现过程。
- 从具体实践中提炼出的通用知识。

## 方案

站点使用 TypeScript 配置 VitePress，把 Markdown 编译为静态页面。工程脚本同样使用 TypeScript，并在持续集成中执行严格类型检查。所有分支在推送后都会执行敏感信息检查和构建验证，只有 `main` 分支会部署到 GitHub Pages。

```text
Markdown
  → 敏感信息检查
  → TypeScript 类型检查
  → VitePress 构建
  → GitHub Pages
```

## 内容安全

这个仓库按照公开互联网内容管理：

1. 原始工作日志和截图不进入仓库。
2. 示例使用公开占位符，并重新编写为最小示例。
3. Git hook 在提交前扫描暂存文件。
4. 持续集成再次扫描全部文件。
5. 自动扫描通过后仍需人工复核。

## 验证

本地使用以下命令执行与持续集成相同的主要检查：

```bash
pnpm check
```

检查成功代表站点可以构建，并不代表内容一定适合公开。内容是否涉及业务秘密、用户信息或受限制代码，最终仍需要作者判断。

## 后续

- 随着文章增加，再引入自动生成的时间线和标签页。
- 定期清理失效链接。
- 对脱敏规则的误报和漏报进行复盘，但不把真实敏感词提交到公开仓库。
