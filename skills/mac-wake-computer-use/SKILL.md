# Mac 闲置唤醒与继续操作

目标：通过正常 Computer Use 唤醒入口恢复桌面，验证真实输入和点击后，继续用户原任务。首次锁定错误不一定代表必须人工解锁，也不能直接忽略。

## 恢复流程

1. **先保留现场**：在调用桌面工具前运行只读检查：

   ```sh
   python3 "${CODEX_HOME:-$HOME/.codex}/skills/mac-wake-computer-use/scripts/check_state.py"
   ```

   保存时间、主显示器睡眠状态、会话锁定标志、HID 闲置秒数。脚本只诊断，不唤醒、不解锁、不产生输入。查询失败保留未知，不当作解锁证据。

2. **正常读取桌面**：按当前 `cua_repl` 文档初始化，用 `cua.getState()` 读取桌面；这是本流程的正常唤醒入口。桌面可用则进入步骤 4。

3. **首次报锁定或自动解锁失败**：保留原始错误，先不绑定应用或发送键鼠。再次运行只读检查；必要时在约 30 秒内最多取三份只读快照，避免长期等待或无限重试。

   - 若出现明确状态变化，例如显示器由睡眠转亮、原锁定标志消失，再正常调用 **一次** `cua.getState()`。字段缺失只是变化线索，不证明已解锁；只有桌面接口实际返回可用，才继续。
   - 若持续锁定、没有恢复迹象或这次重读仍失败，停止恢复，说明已尝试正常唤醒并报告阻断；需要时请用户手动解锁。
   - 权限不足、审批拒绝与本地输入触发的保护，不适用反复重试；遵守工具给出的限制，不换接口绕过。

4. **验证输入与点击**：从最新可用状态选择用户原任务的应用，通过原生 Computer Use 做一个可逆、可核对的操作，并读取新的 AX 状态/截图确认结果。

   - 如果原任务没有合适的验证操作，在已获准的浏览器中新开标签页，打开本 skill 的 [本地验证页](assets/control-check.html)。输入本次唯一英文标记（例如 `wake-当前时间`），点击“验证输入并点击”，必须看到同一标记的“验证成功”回显。
   - 只用截图、DOM 赋值或修改页面文件，不能证明本机键鼠恢复。中文 `typeText` 未生效时，可聚焦后改用工具提供的原生 `paste`，再读取输入框确认，不要直接归因于锁屏。
   - 根据最新 UI 状态定位元素，保留一张结果截图，需要交付截图时给出实际图片或文件链接；成功后立即继续原任务，原任务完成后交付结果，而不是停在测试页。

## 范围与证据

- 本机 2026-11-01 在 macOS 27.0.1、接电且已有登录会话中，两次分别连续闲置约 2 小时、4 小时的自然关屏检查，都出现首次报错、状态变化后正常重读恢复，随后真实输入和点击成功。具体内部原因未确认，不能声称验证了连续闲置 8 小时。
- 当时屏保与熄屏后密码要求均为“永不”，接电 30 分钟关闭显示器。它们是实验背景，不是本 skill 要自动修改的设置；显式锁屏、注销、重启和权限问题需分别判断。
- 不更改认证、权限、电源或 Locked use 配置，不输入系统密码，不用 AppleScript、CGEvent、终端快捷键等替代正常解锁，也不启动常亮或长期监控。
- 简要记录首次返回、状态变化、是否重读及输入/点击结果；失败与后续成功都保留。实际唤醒和输入会改变闲置现场，事后不能声称连续闲置未受影响。

完整实测见 [Journal 实践记录](https://sklme.github.io/journal/knowledge/engineering/macbook-remote-development-codex-desktop-access)。持续锁定时需结合 [OpenAI 官方 Locked use 说明](https://learn.chatgpt.com/docs/computer-use#locked-use) 排查；它仅在已启用且获授权的任务中提供有限的自动解锁，本机输入可能暂停该能力，不能由本 skill 代替配置或认证。
